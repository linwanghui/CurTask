# 宠物技能配置与实现说明

更新日期：2026-09-09。以下按当前代码和配置整理，龙宝宝、小蜜蜂各一张表。修改数值后同步修改本文件和公共技能表中的说明文字。

## 公共规则与配置分工

- `Game_Bundles/73_ZRSJZ/Scripts/ZRSJZ_Constant.ts` 是配置入口。`ZRSJZ_PET_SKILL_CONFIG` 只保留 `Name`、`Kind`、`Unlock`、`GeneLevel`、`Description`、`Animation`、`ReleaseEvent`，用于通用介绍、解锁和宠物施法动画。不要在此添加弹体、治疗、护盾等专属数值。
- 每个技能的具体数值写在下表对应的独立常量中，由 `ZRSJZ_PET_SKILL_EFFECT_CONFIG` 按技能名登记。`ZRSJZ_PetService.GetSkill` 供界面读取基础信息，`GetBattleSkill` 合并基础信息与专属参数供战斗和被动属性计算使用。基础信息与数值各有唯一来源；描述文字不会改变效果。
- 槽位索引：0 普攻、1 玩家属性被动、2 基因主动、3 视频主动。购买解锁普攻；学习 Lv.5 技能基因解锁被动，学习 Lv.15 技能基因解锁第三技能；第四技能通过视频成功回调永久解锁。对应基因节点类型必须为“技能”。
- 主动/普攻要求宠物出战并初始化、主人与宠物存活、战斗未暂停或结束、节点有效、技能解锁且冷却结束、当前没有其他施法。没有随机触发概率。属性和可施放技能在宠物初始化时读取，修改后重新进入战斗验证。
- 龙宝宝优先级：星爆 → 星陨 → 虚能魔弹；小蜜蜂：晶能屏障 → 蜂群部署 → 纳米修复。修改子类 `GetSkillPriority` 可调整顺序。玩家属性被动不占动画轨道，也不因宠物倒地而自动移除。
- 技能由宠物 Spine 释放事件启动：默认普攻 `gongji`，主动 `jineng`。一次施法只执行一次。效果成功执行后进入冷却，普通攻击冷却再除以宠物攻速倍率，主动冷却不受攻速影响。缺失事件或执行失败打印警告并等待1秒重试，不以超时补发效果。
- 施法期间霸体但正常扣血，非致死受击不打断；死亡取消施法。持续技能和特效由父类随战斗计时，暂停冻结，宠物自身死亡、主人死亡、战斗结束、主人节点销毁或宠物停用时清理。
- 下表距离为游戏坐标单位，时间为秒，伤害以宠物最终攻击力为基数；实际敌人扣血仍经过敌人受伤逻辑。

小蜜蜂开始施法后，不在释放事件重复检查距离、血量和敌人范围，避免施法期间移动造成空放。屏障和蜂群缺失预制体时仍返回失败。宠物 `gongji`、`jineng` 事件都在对应动画约0.3333秒。

蜂群未附身最长存在10秒，成功附身后延长到足够完成3秒附身。飞行中目标失效或离开范围会重选；附身后不因距离变化更换目标，目标失效即结束。麻痹独立记录来源，销毁时仅清理自身控制。同目标同种附着特效复用并延长显示。

玩家分次回血目前为 `ZRSJZ_PET_HEAL_CONFIG.Duration=0.8`、`TickInterval=0.3`；实现按 `round(Duration/TickInterval)` 分成3份均匀恢复，累计取整保留总量。`FloatTextHeight=420`。多份治疗可叠加，满血溢出不保留。`73_ZRSJZ/Prefabs/Effect/血量恢复` 通过主包对象池动态加载，放在地图特效层显示实际恢复的 `+数值`，0.7秒内上浮后回收；异步返回时若战斗/玩家已失效则回收，不残留到新场景。

## 后续修改与排查

- 改技能数值：修改上述专属常量；改解锁、名称、说明、宠物动画：修改公共表。新增技能要同时登记专属参数映射，并在对应宠物子类中实现，不能只增加描述。
- 改触发条件：修改 `CanUseSkill` 并同步 `GetSkillCondition`；改效果：修改 `NormalAttack` / `ActiveSkill`，成功返回true，失败返回false。不要在条件判断中直接结算伤害。
- 有动画没效果：开启宠物组件 `DebugSkills`，检查解锁、条件、冷却、实际Spine事件与缺失预制体提示。星陨另需检查特效 `hit` 事件；星爆当前特效没有独立爆炸事件，爆炸时机由专属 `Duration` 控制。
- 预制体绑定：龙宝宝为 `BoltPrefab` / `MeteorPrefab` / `NovaPrefab`；小蜜蜂为 `RepairPrefab` / `ShieldPrefab` / `SwarmPrefab` / `ParalysisPrefab`。特效父类保留美术缩放和内部偏移，并统一处理暂停和清理。
- 主包读取DLC资源前必须判断 `ZRSJZ_UIManager.ZRSJZ_DLC` 为true。`InitDLC` 负责初始化分包并在成功后设置此标志；回血数字始终使用主包资源。
- 修改后刷新资源并重新进入战斗验证。编辑器编译通过不代表实战视觉效果已验证。

## 敌方伤害与血条

敌人刀击、Boss普通攻击和范围技能、轰炸、喷火、子弹均支持宠物受伤。公共入口为主包 `Service/ZRSJZ_FriendlyDamageService.ts`，宠物启用时注册，停用时注销，不从主包获取DLC资源。范围判定检查宠物根节点及有效碰撞体中心；同轮射线按玩家/宠物主体去重。范围伤害先结算宠物，避免玩家致死导致战斗暂停后漏掉同轮宠物伤害。玩家己方攻击仍攻击敌方，没有增加友伤。

新增敌方技能时，范围攻击调用 `DamageArea`，只需补充宠物范围伤害调用 `DamagePetsInRange`，射线调用 `DamageNodes`，单次碰撞调用 `DamageNode`。伤害最终仍进入宠物 `BeHit`，使用宠物防御、霸体和死亡逻辑。

共享 `ZRSJZ_HP.Show` 在生命归零时立即隐藏血条，恢复正数生命后重新显示。玩家致死时在死亡界面处理前更新血条；宠物倒地隐藏，自动复活时恢复。

## 死亡复活与施法移动

`ZRSJZ_PET_BATTLE_CONFIG.ReviveSeconds=-1` 表示宠物死亡后本局不再复活；非负数表示等待相应秒数、且主人存活和战斗继续时复活。当前配置为-1。主人死亡时宠物也死亡，立即隐藏模型和血条、停止技能，并在update中关闭碰撞；死亡界面暂停战斗也会处理。当前两只宠物资源没有死亡动作，不额外添加死亡动画。

宠物从开始施法到收招结束停止跟随、回位传送和悬浮，清除跟随速度，施法结束后恢复跟随。龙宝宝对敌技能在施法前面向范围内最近敌人；小蜜蜂蜂群部署在范围内存在敌人时面向敌人，治疗和护盾保持原朝向。新增宠物可覆写 `GetSkillFacingTarget` 指定对敌技能的朝向目标。

## 施法中断恢复与延迟召回

主人死亡时宠物同步进入死亡流程，取消已有施法并清理效果。战斗结束、宠物死亡或节点失效需要取消时，由ResetCast统一重置动画、施法标记与速度，使旧轨道回调失效，避免残留技能动画。

超距召回通过RequestRecall排队，施法动画和收招结束后才在Follow执行；后续新增强制召回逻辑也应调用这个入口，不要直接传送或重建宠物。已有落地特效独立在场景中执行，不因召回清除。


小蜜蜂新皮肤“樱羽灵蜂”为樱花粉白机械蜂，存档键仍为“蜜蜂侠客”，保留购买与穿戴记录。`PetSkinSpineSkin=pifu_yinghua`，`PetSkinSwarmSkin=pifu_yinghua`；蜂群部署生成时读取当前穿戴皮肤，为每只小机械蜂设置对应皮肤并循环播放移动动画。后续可在 `ZRSJZ_PET_SKIN_CONFIG` 单独设置召唤物皮肤；未配置时沿用宠物皮肤名，资源缺失时回退 default。


## 双人出战与大厅展示

玩家1沿用 `CurPet`，玩家2使用 `Player2Pet`。通过 `GetBattlePet(playerIndex)` / `SetBattlePet(petName, playerIndex)` 查询和设置，索引为0或1。旧档的玩家1选择保留，玩家2默认不出战。购买、等级、基因、技能解锁与皮肤所有权仍共享 `PetData[petName]`，穿戴选择通过 `PlayerSkins[0/1]` 分别保存，允许两名玩家选择同一宠物。

宠物界面的玩家按钮切换当前编辑的出战配置；战斗生成、玩家被动加成、宠物背包容量分别读取所属玩家的选择。`ZRSJZ_Start` 在 DLC 开启时，将对应宠物外观放入 Player1/宠物、Player2/宠物，循环播放 daiji，选择或皮肤改变时刷新；大厅只实例化外观，不启动宠物战斗脚本。


皮肤穿戴接口 `GetCurrentSkin(petName, playerIndex)`、`UseSkin(petName, skinName, playerIndex)` 与属性接口 `GetPetStats(petName, playerIndex)` 均支持玩家索引0/1。旧档第一次读取会把旧穿戴选择复制到两名玩家，此后独立保存；切换宠物后仍记住该玩家对每只宠物的皮肤选择。皮肤弹窗从宠物界面接收玩家索引，大厅、战斗本体、皮肤属性和召唤蜂群均按所属玩家读取。
