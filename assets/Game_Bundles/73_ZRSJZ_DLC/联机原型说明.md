# 联机原型 · 交付说明

## 好友合作 v6（当前版本）

- 门/任务点改为加载时固定的场景局部路径标识，不依赖世界坐标或节点排序。任务点引用保留在缓存中，任务状态成功应用后才推进轮次；完成/失败后两端关闭任务点和小地图标记。
- 服务端保留本局任务结果和已开门记录，客户端入场及每 5 秒请求补发；重复结果不会重复发奖。开门立即解除阻挡，不再等待动画回调。
- 小地图启用第二玩家位置，使用队友实时坐标并以青色区分；队友离场隐藏。
- 暂停按玩家分别记录，任意一方暂停就停住双方。暂停期间冻结局内物理、角色 Spine、AI/子弹及游戏计时，服务端拒绝新的伤害消息。不能单方面解除另一人的暂停。
- 广告播放仅在双方确认暂停后启动，等待界面显示“等待另一个玩家重连”；奖励/关闭/失败/回前台释放等待，后台也发出等待通知。等待上限 180 秒，实际断线仍沿用转单机规则，不是完整断线重连系统。广告 SDK 行为需真机验收。
- 必须同时升级客户端和云端 `server.py` 至 v6 并重启服务，无新增 Python 依赖。当前回归包含任务补发/接取重试/去重、开门补发、双人暂停所有权、广告确认/取消/单次奖励、原有战斗和撤离；小地图显示和真实 SDK 需双端人工测试。

## 好友合作 v5（历史记录）

- 任意玩家接取特别行动后，由房主统一确认并同步双方。高价值目标只由房主生成，通过已有怪物同步共享，任意玩家击杀后双方完成、各自领取原配置奖励；同一任务轮次的重复状态不会重复发奖。
- 破壁行动是否出现由服务端统一按 30% 抽取。邮箱内容、密码和物资仍独立；双方各自开完全部箱位才完成。队友离场转为单机后，只需完成自己剩余箱位。
- 坚守轰炸区同步接取点圆心和任务倒计时，由房主检查双方是否在区域内并同步结果。轰炸效果仍由各端运行，并非逐颗同步。
- 同步实际可见的头盔、防弹衣、背包和耳机附件，穿脱后更新队友外观；不上传库存 ID、属性或存档。
- 客户端与云端 `server.py` 必须一起升级至 v5，重启服务；无需增加依赖。自动测试覆盖真实双客户端消息转发、任务权威判定、双方开箱、重复发奖保护、装备穿脱附件和原有撤离接管。实际画面与完整双端任务流程仍需人工验收。

## 好友合作 v4（历史记录）

- 同步队友当前武器、武器皮肤、Spine 瞄准骨骼及攻击动画轨道；远端只播放外观，不重复造成伤害。
- 房卡/广告门按地图位置识别并同步开启。服务端先授予唯一解锁凭证，拿到凭证的客户端才扣房卡，再广播开门；同时点击的另一端不扣卡。扣卡失败会释放凭证。
- 已开启的门在本局转为单机后保持开启。保险门的先锋行动限制不变；掉落箱依旧各自独立。
- 必须同时更新客户端与云服务器 `server.py` 并重启服务；v4 客户端会拒绝旧服务端并显示升级提示，无新增 Python 依赖。
- 仍需双端实机检查不同枪械/皮肤、左右瞄准、快速切枪，以及同时用房卡和看广告开同一扇门。极端断线时，已扣卡的一端保留开门成果；不承诺跨断线的分布式扣费绝对一致。

## 好友合作 v3（历史记录）

撤离提示更新：普通撤离点和 VIP 安全撤离成功时，立即发送 `finish_battle(reason=evacuated)`；不论房主还是队友撤离，另一端显示“队友已撤离，已转为单机，可继续战斗和撤离”。死亡/失败结算不会误报撤离，后续 socket 关闭也不会覆盖撤离提示。此更新需要同时覆盖云服务器的新版 `server.py` 并重启，协议版本号仍为 v3。

本轮修正联机界面预制体：背景保持 3:2、按钮保持 3:1；关闭按钮不再把长条图压成方形。保留现有静态节点、数字键盘、选图和战备检查，没有新增匹配或剪贴板权限。

局内实现：

- 房主运行普通敌人和 Boss 的 AI；队友端只创建对应副本，同步位置、朝向、动作、瞄准、血量、死亡。
- 队友玩家与宠物造成的伤害、眩晕、牵引发给房主处理。双方可同时攻击同一个敌人。
- 敌方子弹、喷火和 Boss/近战范围攻击转发到队友端；队友玩家子弹仅作表现，防止二次扣血。不支持玩家互伤。
- 死亡只处理一次；两端分别生成掉落箱，箱子内容、搜索、领取和仓库存档均不上传。击杀按团队击杀计入各自本地逻辑。
- 同步已配置的星核幼龙、小蜜蜂的外观、位置和基础动作；实际宠物 AI/技能由所属客户端运行。技能命中共享敌人，但召唤蜂群及技能特效尚未完整镜像。
- 怪物会选择两名玩家中的近处目标。联机时房主打开本地面板或等待复活不再停止怪物 AI。

房主离场后的单机接管：房主撤离结算、退出或连接中断后，尚未结算的玩家自动转为单机继续战斗和撤离，不再被强制暂停或退出。保留本地地图、背包、箱子、计时及撤离进度；怪物副本以最后收到的血量就地接管 AI，不恢复满血、不重复掉落。已经死亡或被移除的敌人不会复活。未加载完的快照继续加载并只接管一次；开场未收到任何快照时使用本地图原生敌人兜底。原有暂停/死亡界面保持不变，不自动复活。突然断线以最后收到的快照为准，可能存在短暂的网络状态差异。本修正仅需更新客户端，服务端协议仍为 v3。

边界：仍是好友合作测试版，不是完整上线版。无匹配、断线重连、联机房主迁移（离场后是单机，不是新房主）；没有同步先锋行动等局内随机事件、完整装备附件、组队撤离/队友复活流程。撤离和物品消耗沿用各自本地流程。请使用备份存档测试。

部署：将 `C:/Users/Administrator/Desktop/SJZonline/server.py` 覆盖云服务器的同名文件，关闭旧进程后用原启动脚本重新启动。启动输出应包含 `v3`。服务器地址仍为 `ws://111.229.178.69:8765`；v2 服务端与此客户端不兼容。本机文件已更新，未操作云服务器。

验证：本机真实 WebSocket 两客户端测试通过；敌人生产代码的伤害路由、死亡幂等、独立掉落入口和离线伤害单元测试通过；协议非法字段/权限检查通过。两游戏包类型检查无错误，共享项目依赖另有 18 条类型诊断，未改动其他游戏。尚未运行 Cocos 双窗口画面及物理测试。

手动验收建议：

1. 两端用同一新版客户端和 v3 服务，创建/输入房号，切图并检查战备、准备。
2. 攻击同一个普通敌人及 Boss：两边血量与死亡一致，不能重复出箱；各自开箱不影响另一边。
3. 一方携带宠物，另一方查看跟随/攻击；测试喷火、Boss 范围伤害和宠物眩晕。
4. 再进入一局，确认没有旧队友、旧怪物或旧宠物；测试队友退出、房主退出和服务器中断。
